================================================================================
 COMMANDS_CASCADE.txt — depth cascade: one module path per rate, shared backbones
 rev 2026-10-07. Everything runs on the server, from the jscc/ directory.
 GPUs: ONLY 2, 3, 4 and 5. GPU 0 (kept free) and GPU 1 (broken) are never used.
================================================================================

THE IDEA (docs/CASCADE.md). Between the backbone encoder and decoder sits a stack
of small modules that step down the rate ladder 1/8 -> 1/12 -> 1/16 -> 1/24 -> 1/48
with fewer channels each. Rate k sends the code of stage k; the receiver runs the
decoder-side modules of that stage and then the shared backbone decoder. It starts
as EXACTLY the prefix model (zero-initialised stages over a truncation skip), so it
can be fine-tuned from your wave-1 checkpoints and cannot start worse.
Judgement of the idea, related work, venue: docs/ASSESSMENT.md.

WHAT THIS WAVE ANSWERS (400-epoch fine-tunes of the wave-1 swin and vit
checkpoints, the p1 recipe, against a control fine-tuned the same way on the SAME
five budgets, no modules):

  1. does a rate-specific path help at all?      linear (depth 0)  - control
  2. does capacity beyond a linear map help?     all-mlp           - linear
  3. does spatial context help, and at which     mixed (mlp, mlp, spatial, spatial)
     rate?                                       and all-spatial, read per CBR
  4. does the top rate (1/8) recover the nested  every arm - control at 1/8
     tail penalty (0.3-0.7 dB vs a specialist)?
  5. gradient sharing: top rate vs low rates     mixed with --cascade-grad 0.5
  6. "deeper net for fewer channels"?            depths 1 2 3 4 vs 4 3 2 1

  stage (1)     (2)     (3)     (4)     the stage goes from ... to ... (CBR)
        1/8->1/12 1/12->1/16 1/16->1/24 1/24->1/48
  code  swin: 192 -> 128 -> 96 -> 64 -> 32 channels per 16x16-px position
        vit : 48 -> 32 -> 24 -> 16 -> 8 reals per 8x8-px patch (6 -> 1 tokens)

  arm                         kinds (stages 1-4)     depths    swin   vit
  control (no modules)        -                      -         S0     T0
  linear                      mlp mlp mlp mlp        0 0 0 0   S1     T1
  all-mlp                     mlp mlp mlp mlp        1 2 3 4   S2     T2
  mixed (the default)         mlp mlp SP  SP         1 2 3 4   S3     T3
  all-spatial                 SP  SP  SP  SP         1 2 3 4   S4     T4
  mixed, grad share 0.5       as mixed               1 2 3 4   S5     T5
  mixed, depths reversed      as mixed               4 3 2 1   S6     T6
  (SP = swin windows for swin, global attention for vit; extra parameters at the
   defaults: swin 1.76 M = +33% of 5.3 M, vit 2.71 M = +1.9% of 142 M)

14 jobs on 4 cards (2, 3, 4, 5), queued per card in priority order. By your wave-1
throughput a vit job is about 3.8 h and a swin job about 2.7 h (tools/probe.py
prints ms/step, section 2): the whole sheet is about 12 h. The six essential jobs
(both controls, all-mlp and all-spatial for each interface: T0 T2 T4 S0 S2 S4) are
the first one or two jobs of their queues and finish about 6.5 h in; they answer
questions 1-4. Stop there for an early look if you need the cards.

  card   queue (in order)
  GPU 2  T0 vit control          -> T3 vit mixed          -> T5 vit mixed, grad 0.5
  GPU 3  T2 vit all-mlp          -> T1 vit linear         -> T6 vit mixed, depths 4 3 2 1
  GPU 4  T4 vit all-attention    -> S4 swin all-window    -> S3 swin mixed -> S5 swin mixed, grad 0.5
  GPU 5  S0 swin control         -> S2 swin all-mlp       -> S1 swin linear -> S6 swin mixed, depths 4 3 2 1

GOTCHA: these are FINE-TUNES. The cascade starts from the wave-1 weights, so its
validation PSNR at epoch 40 must be within ~0.3 dB of the control's. A cascade arm
more than 1 dB below the control at epoch 40 means something is wrong: stop it and
send the log.
GOTCHA: the control is trained on the five predefined CBRs (--rate-sampling grid),
NOT the continuous-rate wave-1 model: a cascade can only be trained on its levels,
so the fair control sees the same budgets.
GOTCHA: a cascade only evaluates its five levels (--eval-cbrs must be among them);
it has no in-between budgets.
GOTCHA: every command below sets CUDA_VISIBLE_DEVICES to 2, 3, 4 or 5 itself, and
none of them uses a bare `wait` or `nvidia-smi` without -i, so whatever you run on
GPU 0 (even from the same shell) is neither blocked nor touched.

 0. GET THE CODE, ENVIRONMENT
--------------------------------------------------------------------------------

cd ~/projects
git clone https://github.com/matthewwang16czap/JSCCwClaude.git jscc_cascade   # or: cd jscc_cascade
cd jscc_cascade && git checkout claude/gifted-newton-cfldb8 && git pull && cd jscc

# the wave-1 checkpoints live in the old tree: make its history/ visible here,
# the new runs land in the same place
ln -sfn ~/projects/jscc_clean/jscc/history history

export JSCC_DATA_ROOT=$HOME
export PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True   # less fragmentation
export CUDA_DEVICE_ORDER=PCI_BUS_ID    # CUDA index N = nvidia-smi index N. Without it CUDA may
                                       # number identical cards differently, and "2" could be
                                       # the card you keep free. Keep it set in this shell.

W1S=history/swin_base_awgn_DIV2K_256_w1/models/last.pt
W1V=history/vit_p8d768x10s4_awgn_DIV2K_256_w1/models/last.pt
ls -l $W1S $W1V                                           # both must exist

FT="--trainset DIV2K --validset DIV2K --testset Kodak --img-size 256 \
  --batch-size 16 --channel-type awgn --snrs 1 4 7 10 13 --snr-range -2 22 \
  --amp --training --max-epoch 400 --valid-freq 40 --lr 5e-5 --warmup-steps 200 \
  --tag c1"
SW="--backbone swin --pretrained $W1S"
VI="--backbone vit --pretrained $W1V"
CS="--cascade --mod-lr-mult 4"      # cascade on; its new modules learn 4x faster

--------------------------------------------------------------------------------
 1. CPU GATES — a few minutes. All must pass.
--------------------------------------------------------------------------------

python -m pyflakes main.py engine.py configs data net utils tools alloc
python tools/smoke.py            # ends with "all checks passed"; [cascade] is new
python tools/check_channel.py    # ends with "channel conventions hold"

# FREE CHECK (minutes, cards 2-5, one run each; test only, no training). A cascade
# with untrained modules loaded from the wave-1 checkpoint IS that prefix model, so
# its Kodak table must equal the prefix model's at the five CBRs (same code, same
# channel draws; the prefix model is re-scored here so an old test.json cannot
# confuse it):
TEST="--testset Kodak --img-size 256 --channel-type awgn --snrs 1 4 7 10 13 --amp --tag t0"
CUDA_VISIBLE_DEVICES=2 python main.py $TEST --backbone swin --pretrained $W1S \
  > c1_t0_swin_prefix.out 2>&1 &
P2=$!
CUDA_VISIBLE_DEVICES=3 python main.py $TEST --backbone vit --pretrained $W1V \
  > c1_t0_vit_prefix.out 2>&1 &
P3=$!
CUDA_VISIBLE_DEVICES=4 python main.py $TEST --backbone swin --cascade --pretrained $W1S \
  > c1_t0_swin_cascade.out 2>&1 &
P4=$!
CUDA_VISIBLE_DEVICES=5 python main.py $TEST --backbone vit --cascade --pretrained $W1V \
  > c1_t0_vit_cascade.out 2>&1 &
P5=$!
wait $P2 $P3 $P4 $P5               # only these four, not anything else running from this shell
python tools/compare_runs.py history/swin_base_awgn_DIV2K_256_t0 \
  history/swin_base_awgn_DIV2K_256_casc-mmss-d1234_t0 --test
python tools/compare_runs.py history/vit_p8d768x10s4_awgn_DIV2K_256_t0 \
  history/vit_p8d768x10s4_awgn_DIV2K_256_casc-mmaa-d1234_t0 --test
# the second row of each: +0.000 at every CBR (|diff| < 0.005). If not, STOP and send
# both tables and c1_t0_*.out; do not start section 3. (Both prefix rows should also
# match your wave-1 / retest Kodak numbers to a few hundredths.)

--------------------------------------------------------------------------------
 2. GPU PROBE — about a minute per line: real peak memory and speed at batch 16

CUDA_VISIBLE_DEVICES=2 python tools/probe.py --backbone vit --batch-size 16 --amp
CUDA_VISIBLE_DEVICES=3 python tools/probe.py --backbone vit --cascade --batch-size 16 --amp
CUDA_VISIBLE_DEVICES=4 python tools/probe.py --backbone swin --batch-size 16 --amp
CUDA_VISIBLE_DEVICES=5 python tools/probe.py --backbone swin --cascade --batch-size 16 --amp

# Keep "reserved" at or below ~22 GiB. If the vit cascade is above that, add
# --batch-size 8 to every vit line in section 3 (accumulation keeps the effective

--------------------------------------------------------------------------------
 3. THE WAVE — 14 fine-tunes, queued on cards 2-5 (jobs on one card run in order)
--------------------------------------------------------------------------------

# GPU 2 — T0 vit control (grid, no modules);  T3 vit mixed (the default);  T5 vit mixed, grad share 0.5
nohup bash -c "
CUDA_VISIBLE_DEVICES=2 python main.py $FT $VI --rate-sampling grid > c1_gpu2_T0_control.out 2>&1 ;
CUDA_VISIBLE_DEVICES=2 python main.py $FT $VI $CS > c1_gpu2_T3_mixed.out 2>&1 ;
CUDA_VISIBLE_DEVICES=2 python main.py $FT $VI $CS --cascade-grad 0.5 > c1_gpu2_T5_grad05.out 2>&1
" > /dev/null 2>&1 &

# GPU 3 — T2 vit all-mlp;  T1 vit linear (depth 0);  T6 vit mixed, depths 4 3 2 1
nohup bash -c "
CUDA_VISIBLE_DEVICES=3 python main.py $FT $VI $CS --mod-kinds mlp > c1_gpu3_T2_allmlp.out 2>&1 ;
CUDA_VISIBLE_DEVICES=3 python main.py $FT $VI $CS --mod-kinds mlp --mod-depths 0 > c1_gpu3_T1_linear.out 2>&1 ;
CUDA_VISIBLE_DEVICES=3 python main.py $FT $VI $CS --mod-depths 4 3 2 1 > c1_gpu3_T6_deprev.out 2>&1
" > /dev/null 2>&1 &

# GPU 4 — T4 vit all-attention;  S4 swin all-window;  S3 swin mixed (the default);  S5 swin mixed, grad share 0.5
nohup bash -c "
CUDA_VISIBLE_DEVICES=4 python main.py $FT $VI $CS --mod-kinds attn > c1_gpu4_T4_allattn.out 2>&1 ;
CUDA_VISIBLE_DEVICES=4 python main.py $FT $SW $CS --mod-kinds swin > c1_gpu4_S4_allswin.out 2>&1 ;
CUDA_VISIBLE_DEVICES=4 python main.py $FT $SW $CS > c1_gpu4_S3_mixed.out 2>&1 ;
CUDA_VISIBLE_DEVICES=4 python main.py $FT $SW $CS --cascade-grad 0.5 > c1_gpu4_S5_grad05.out 2>&1
" > /dev/null 2>&1 &

# GPU 5 — S0 swin control (grid, no modules);  S2 swin all-mlp;  S1 swin linear;  S6 swin mixed, depths 4 3 2 1
nohup bash -c "
CUDA_VISIBLE_DEVICES=5 python main.py $FT $SW --rate-sampling grid > c1_gpu5_S0_control.out 2>&1 ;
CUDA_VISIBLE_DEVICES=5 python main.py $FT $SW $CS --mod-kinds mlp > c1_gpu5_S2_allmlp.out 2>&1 ;
CUDA_VISIBLE_DEVICES=5 python main.py $FT $SW $CS --mod-kinds mlp --mod-depths 0 > c1_gpu5_S1_linear.out 2>&1 ;
CUDA_VISIBLE_DEVICES=5 python main.py $FT $SW $CS --mod-depths 4 3 2 1 > c1_gpu5_S6_deprev.out 2>&1
" > /dev/null 2>&1 &

# --- right after launch -----------------------------------------------------------
grep -h "cascade:" c1_gpu*.out        # modules' parameters, kinds, depths, levels: as in the table above
grep -h "loaded" c1_gpu*.out          # controls: 0 missing. Cascade arms: only the cascade's own
                                      #   tensors missing (a few hundred), 0 unexpected
grep -h "prefix checkpoint" c1_gpu*.out   # the vit cascade arms: levels seeded from the gain/DC tables
tail -n 2 c1_gpu*.out                 # img/s, loss, the diag check
nvidia-smi -i 2,3,4,5                 # <= ~22 GiB per card (-i: never queries the broken card)

# --- while it runs ----------------------------------------------------------------
grep -h "diag" c1_gpu3_T2_allmlp.out | tail -3     # swapped must stay well below psnr
grep -h "non-finite" c1_gpu*.out                   # skipped optimiser steps: expect none
ls history/ | grep _c1$                            # the run directories (names in section 4)

# the validation at epoch 40 (~25 min into each job): cascade arms within ~0.3 dB of
# their control. Run the swin line again as S2, S4 ... start (each job has to exist).
python tools/compare_runs.py history/vit_*_grid_c1 history/vit_*casc*_c1 --window 1 --upto 40
python tools/compare_runs.py history/swin_*_grid_c1 history/swin_*casc*_c1 --window 1 --upto 40

--------------------------------------------------------------------------------
 4. READING THE WAVE (send back everything this section prints)
--------------------------------------------------------------------------------

VT=history/vit_p8d768x10s4_awgn_DIV2K_256
SWH=history/swin_base_awgn_DIV2K_256

# 4a. validation windows: the last 5 validations (epochs 240-400), differences vs the
#     first row (the control), per CBR, with the sd across the window
python tools/compare_runs.py ${VT}_grid_c1 ${VT}_casc-mmmm-d0000_c1 ${VT}_casc-mmmm-d1234_c1 \
  ${VT}_casc-mmaa-d1234_c1 ${VT}_casc-aaaa-d1234_c1 ${VT}_casc-mmaa-d1234_cg0.5_c1 \
  ${VT}_casc-mmaa-d4321_c1 --window 5
python tools/compare_runs.py ${SWH}_grid_c1 ${SWH}_casc-mmmm-d0000_c1 ${SWH}_casc-mmmm-d1234_c1 \
  ${SWH}_casc-mmss-d1234_c1 ${SWH}_casc-ssss-d1234_c1 ${SWH}_casc-mmss-d1234_cg0.5_c1 \
  ${SWH}_casc-mmss-d4321_c1 --window 5

# 4b. the Kodak test (last checkpoint, native resolution), paired over images:
#     mean difference, 95% bootstrap CI over the 24 images, share of images won
#     vs the control (questions 1, 2, 3, 4)
python tools/paired.py ${VT}_grid_c1 ${VT}_casc-mmmm-d0000_c1 ${VT}_casc-mmmm-d1234_c1 \
  ${VT}_casc-mmaa-d1234_c1 ${VT}_casc-aaaa-d1234_c1
python tools/paired.py ${SWH}_grid_c1 ${SWH}_casc-mmmm-d0000_c1 ${SWH}_casc-mmmm-d1234_c1 \
  ${SWH}_casc-mmss-d1234_c1 ${SWH}_casc-ssss-d1234_c1

# 4c. which module kind at which stage (a factorial: early stages x late stages)
#     late stages (-> 1/24, -> 1/48):  mixed - all-mlp, read at 1/24 and 1/48
#     early stages (-> 1/12, -> 1/16): all-spatial - mixed, read at 1/12 and 1/16
python tools/paired.py ${VT}_casc-mmmm-d1234_c1 ${VT}_casc-mmaa-d1234_c1 ${VT}_casc-aaaa-d1234_c1
python tools/paired.py ${VT}_casc-mmaa-d1234_c1 ${VT}_casc-aaaa-d1234_c1
python tools/paired.py ${SWH}_casc-mmmm-d1234_c1 ${SWH}_casc-mmss-d1234_c1 ${SWH}_casc-ssss-d1234_c1
python tools/paired.py ${SWH}_casc-mmss-d1234_c1 ${SWH}_casc-ssss-d1234_c1

# 4d. training strategy and depth schedule, against the mixed default (questions 5, 6)
python tools/paired.py ${VT}_casc-mmaa-d1234_c1 ${VT}_casc-mmaa-d1234_cg0.5_c1 ${VT}_casc-mmaa-d4321_c1
python tools/paired.py ${SWH}_casc-mmss-d1234_c1 ${SWH}_casc-mmss-d1234_cg0.5_c1 ${SWH}_casc-mmss-d4321_c1

# 4e. the metrics the loss did not train on (fp32; the arms are all MSE-trained)
python tools/paired.py ${VT}_grid_c1 ${VT}_casc-mmaa-d1234_c1 --metric msssim
python tools/paired.py ${VT}_grid_c1 ${VT}_casc-mmaa-d1234_c1 --metric lpips_vgg
python tools/paired.py ${SWH}_grid_c1 ${SWH}_casc-mmss-d1234_c1 --metric msssim
python tools/paired.py ${SWH}_grid_c1 ${SWH}_casc-mmss-d1234_c1 --metric lpips_vgg

# Decision (docs/ASSESSMENT.md has the gates):
#   any arm - control >= +0.3 dB mean over the CBRs, CI above 0 at >= 3 CBRs
#                                                    -> the idea lives: wave c2
#   every arm < +0.1 dB                              -> stop: the nesting penalty is
#                                                       not what a cascade removes
#   linear > control at 1/48-1/24                    -> rate-specific paths help alone
#   only the module arms gain                        -> capacity: add the
#                                                       parameter-matched adapter control
#   a stage's spatial kind wins if +0.05 dB, CI clear of 0, at that stage's CBR
#   d1234 - d4321 > 0 at 1/24 and 1/48               -> depth should grow as rate falls
#   cg0.5 up at 1/8, down at 1/48                    -> the top-rate / low-rate trade
#                                                       is real: wave c2 sweeps it
#   Swin pays +33% parameters: no structural claim from swin until the matched control
