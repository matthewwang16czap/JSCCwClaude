Explainer for the TWC paper draft

Scheduling learned image codes

A base station must deliver one image to each of several users before a deadline, over fading channels, one slot at a time. This page shows the setup and how each scheduler decides. It then plays one frame slot by slot, with the baselines and our method on the same channel, and ends with the results measured on the real codec.

1 · SETUP

Each image is coded once, then sent phase by phase

A learned code (deep JSCC) encodes every image once into a prefix of 6 phases. The first phase gives a coarse picture and each later phase refines it. Each slot carries one phase of one user. Before each slot, every user reports its channel for that slot. The scheduler never sees future slots. At the deadline, each user decodes the phases it has received.

K = 8 users, T = 24 slotsin the paper; this page uses 4 users and 12 slots, also 3 phases per user on average

2 · WHAT A SLOT IS WORTH

Which phase a good slot carries matters

For our code, received phases combine as sensitivity-weighted MMSEs: each phase's noise counts with its own weight. The first phase carries half of the total weight, so it should go into a good slot. This rule predicts the decoded PSNR with a mean error of 0.055 dB. MIESM, the rule digital system simulation uses (it averages capacity), errs by 0.49 dB on the same code.

Which phase should get the good slot? A medium-detail image; PSNR from the model below.

The model behind every decision on this page. A user holding n phases, received at SNRs g1, …, gn, has distortion

D = Dsrc(n) + C(n) · Σj mj φ(10−gj/10) / (m1 + … + mn),   φ(x) = x / (1 + x/κ),   PSNR = −10 log10 D

Dsrc(n) is the image's distortion with n noise-free phases and C(n) its sensitivity to noise, both calibrated per image. φ(x) is the error of the best estimate of a Gaussian of variance κ seen through noise of variance x. So a user's state is two numbers: n, the phases it holds, and Y = Σ mj φ, their weighted noise.

PF chases peaks in rate; our rule chases peaks in quality. A user whose image is close to its best quality gains little from a good slot and can take a poor one. A user about to send its sensitive first phase waits for a peak.

    7 · WHY IT IS NEAR-OPTIMAL

    One small program per user, then a rule for conflicts

    Because a user's state is just (n, Y), the downlink is a restless bandit. The users are the arms, and a slot activates one of them. Each user's state changes even when it is not served: its channel is redrawn and its deadline gets closer. Putting a price on each slot splits the problem into one small program per user. Those programs give two things: an upper bound on every possible scheduler, and each user's ideal action at the price. A scheduler is then those ideal actions plus a rule for who wins when more users want a slot than it can serve.

    Conflict ruleRanks the users who want the slot byNeedsMeasured
    Whittle indexthe slot price at which the user is indifferent between taking the slot and leaving iteach user's program at many pricesequal to our rule (+0.005 dB); +0.15 dB with 25% of slots lost
    Lagrangian indexthe user's gain from the slot at the bound's priceseach user's program at one set of pricespending (COMMANDS 18.3)
    ID policy (Hong et al.)a fixed order of user IDs, among the users the relaxation would serveeach user's program at one set of pricespending (COMMANDS 18.3)
    Ours: advantage indexthe PSNR gain in this slot minus the gain in a typical slotno program: closed formthe reference

    Our advantage index is the closed-form shortcut to the Whittle index. It compares this slot with a typical one instead of solving the program, and it gives up nothing measurable (+0.005 dB). No causal scheduler, however clever, can beat it by more than 0.23 dB in mean PSNR. The full write-up has the formulation.
